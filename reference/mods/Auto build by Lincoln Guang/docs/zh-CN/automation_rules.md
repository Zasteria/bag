# 自动建造：游戏文件分析与规则说明

[English](../en/automation_rules.md) | 简体中文

## 目标

原版经济自动化的核心排序值来自 `common/employment_systems/00_default.txt` 中的
`building_potential_profit`。这种逻辑适合寻找单体利润，却不能保证食物、建筑材料、
人口必需品和军需品先得到补足。本 Mod 因而采用「需求优先、市场信号决胜」的分层规则。
静态供需、市场价格与饱和度信号先生成初步候选；隐藏 GUI 桥接再读取引擎为普通建筑
计算的实际收入、利润和成本，并在开工前执行玩家选择的最终收益要求。

## 数据依据

分析源为仓库中的 EU5 `common/` 数据集，并与本地 EU5 1.3 安装目录中的同名数据交叉校验。

- 数据中共有 883 个顶层 `building_type` 定义和 85 种商品；其中 13 种商品带有正的
  `food` 数值，因此 `fur`、`beeswax` 等看似不是主粮的商品也计入游戏的食物储备。
- `market_triggers.txt` 和市场属性公开了 `market_food_percentage`、
  `market_monthly_food_balance`、`is_projected_to_run_out_of_food_stockpile`、
  `goods_supply_in_market`、`goods_demand_in_market` 与 `market_price`。
- 建筑触发器中的利润、投入品与产出品查询要求已有建筑实例作用域，不能直接用于未建的
  `building_type` 候选。生成器因此先根据静态目录中的配方进行初选，再通过引擎 GUI getter
  读取候选的实际收入、利润与成本。
- `location_triggers.txt` 公开了按 `building_type` 查询失业人口、既有等级、民用建造数和
  原产工人容量的接口。
- 建筑投入结构中最常见的建造瓶颈集中在 masonry、lumber、tools、glass、paper、stone。
- 原版 `common/prices/00_hardcoded.txt` 将采矿、农业、狩猎、采集和林业五类原产扩建的
  基础金币成本都设为 100。生成器会读取这五项，并校验生成脚本使用的
  `automation_rules.json` 镜像值；这个 100 来自原版，不是独立估算或可调平衡参数。
- 原版原产扩建界面也偏重经济回报。`construct_rgo_upgrade` 是当前地点上的无参数效果；
  调用后仍由原版检查其内部条件。

## 决策管线

每个月的工作分为一次国家级初始化、二十个每日批次和一次最终入队：

1. 国家月度脉冲同步 CMF 模组设置，减少已分配地点的冷却期，并统计本 Mod 确认开工且仍在
   建造的项目。手动建造、道路和其他 Mod 的项目不计入本 Mod 的同时建造上限。
2. 每年 1 月按固定金额或 `monthly_income_total ×4/×6/×8` 重置国家级年度预算池。全部内置
   预设和自定义模板共用该预算池；首次加载时也会初始化。
3. 系统对已分配地点做低成本过滤，并按确定规则分入二十个临时列表。2～21 日每天只处理
   当天列表，避免在同一天扫描全国。每日地点任务上限可设为 1～30。
4. 可选的「独立地点任务」会把地点计算拆成独立事件任务；这不代表游戏使用多个 CPU 线程。
   国家级候选归并、预算、诊断和开工仍按确定顺序执行。
5. 每个地点只保留最强的普通建筑候选和符合条件的原产候选，并让每个候选只进入唯一的
   「食物紧急状态／建造类型」阶段，避免在多个阶段重复评分。
6. 22 日合并本月候选。系统先按玩家设置的四类自动建造顺序处理紧急食物项目，再按同一
   顺序处理其他项目。默认顺序为「升级 → 普通扩建 → 原产扩建 → 新建」。
7. 当前建造类型中能尝试的项目全部检查完后，系统才进入下一类。普通建筑没有通过引擎
   计算的成本、收益或建造条件时，会释放临时预留并继续尝试同类的下一个项目。
8. 只有民用建造队列确实增长后，系统才扣除预算、占用本 Mod 的同时建造名额，并为地点
   设置 3 个月冷却。原产使用原版 `construct_rgo_upgrade`，与普通建筑共用名额，没有独立
   的月度上限。启用上游补建后，真正短缺的上游来源可在普通候选被缺料阻塞时加入对应类别。

玩家设置的是基础 1 项之外的额外同时建造数：0 代表本 Mod 最多同时进行 1 项，599 代表
最多 600 项。系统每月只补足本 Mod 自己的剩余空位；每个地点同一时间最多安排 1 个项目。

## 硬性门槛

候选必须先通过以下条件，不能只凭高价信号入选：

- 建筑质量优先级必须高于 0，除非该建筑被内置预设显式列入允许列表。自定义模板中的 0
  始终表示禁用。
- 建筑在策略允许范围内且不在禁止列表中；特殊建筑需要明确许可。
- 地点没有正在进行的民用建造，且冷却已经结束。
- 开启劳动力保护时，预计可用劳动力必须能在设置期限内填补新增岗位。
- 开启投入品保护时，候选所需工业投入品的供给不得低于需求的 75%。
- 低于策略最低价格比例的过剩产物停止扩建；高价格表示短缺，不会再被误判为超出范围。
- 普通生产建筑必须通过所选引擎收益要求，除非命中战略豁免；没有产出的基础设施不受这项
  收益校验限制。
- 候选的实际建造所需商品，加上同轮已批准项目的预留需求后，必须仍低于停工余量；每种
  所需商品的市场价格也不得高于默认价格的 150%。
- 普通建筑的实际成本加上同轮预留支出后，必须低于剩余年度预算，并在付款后保留设置的
  国库储备；原产改用生成时从原版价格表校验的基础成本 100。只有队列增长确认后才正式
  结算。

## 需求评分

以下分数来自 `policies/automation_rules.json`，可以直接校准。需求分远高于价格代理分。

| 信号 | 分数 |
| --- | ---: |
| 市场预计食物储备耗尽 | +12000 |
| 食物储备不高于 25% | +9000 |
| 食物储备不高于 50% | +6000 |
| 月度食物结余为负 | +4500 |
| 建造所需商品供给/需求不高于 65% | +5000 |
| 建造所需商品供给/需求不高于 90%，或价格高于 125% | +3000 |
| 人口必需品严重/一般短缺 | +2800 / +1400 |
| 军需品严重/一般短缺 | +3500 / +1200 |
| 战时军需额外加分 | +1800 |
| 短缺的上游来源 | +3200 |
| 策略优先商品 | 首项 +600，随后每项 -20 |
| 视频校准建筑质量 | 0～10，每点 +50；可继承前置建筑分数，否则默认为 0 |
| 建筑角色匹配 | +300 |
| 投入品严重不足 | -3000 |
| 纯 Python 测试中的高利润/非负利润/负利润 | +180 / +90 / -180 |
| 同类建筑既有等级 | 每级 -25 |

游戏脚本不会用 `building_potential_profit` 做初选评分。内置预设和自定义模板都以产出商品
价格超过上限时的 +180 作为短缺代理；纯 Python 评估器保留有界利润分用于离线规则测试。
隐藏 GUI 桥接随后校验玩家选择的实际收入、利润或回报率。因此，食物危机中的食物和原产
候选会显著领先奢侈品；供给稳定后，再由市场价格、模板优先级和饱和度区分同类项目。

## 自动建造顺序、收益要求与紧急规则

「自动建造顺序」是全部模板共享、可以拖动的四项列表：

1. 升级建筑
2. 扩建现有普通建筑
3. 扩建原产
4. 新建普通建筑

评分只决定当前类型内部的先后，不能让排在后面的类型提前。某个项目不能开工时，系统会
继续寻找同类项目，当前类型耗尽后才进入下一类。

普通生产建筑的最终引擎校验有四种：

| 设置 | 最终引擎校验 |
| --- | --- |
| 收入 | 实际月度收入大于 0 |
| 利润 | 实际月度利润大于 0 |
| 收入回报率 | 实际月度收入不低于 `实际成本 × 5% ÷ 12` |
| 利润回报率 | 实际月度利润不低于 `实际成本 × 5% ÷ 12` |

五个战略开关彼此独立：

| 开关条件 | 是否优先处理 | 哪些建筑可放宽收益要求 |
| --- | --- | --- |
| 市场预计食物储备耗尽 | 是 | 匹配的普通食物建筑 |
| 食物储备不高于 25% | 是 | 匹配的普通食物建筑 |
| 核心建造所需商品供应低于需求的 65% | 否 | 生产相应商品的建筑 |
| 战争期间军需品供应低于需求的 65% | 否 | 生产相应军需品的建筑 |
| 上游原料低于需求的 65%，并阻塞已开启的战略建筑 | 否 | 生产相应上游原料的建筑 |

两个食物开关既会优先处理食物项目，也会为匹配的普通建筑放宽收益要求。其他三个开关只
放宽收益要求。所有开关都不会绕过年度预算、国库储备、劳动力/投入品保护、建造所需商品、
游戏自身的建造条件、地点队列可用性或本 Mod 的同时建造上限。

## 原产规则

原产只在以下条件同时满足时尝试扩建：

- 尚未完全扩建，且当前工人达到容量的 75%，避免继续扩建缺少工人的原产。
- 原材料属于短缺的食物、建造所需商品，或当前策略的优先商品。
- 国库储备和共享年度预算能够覆盖原版基础成本 100。

调用 `construct_rgo_upgrade = { }` 后，只有地点实际出现民用建造，才会占用名额、设置冷却
并扣除预算，因此原版条件拒绝扩建时不会扣款。

原产地点的最终排序直接合并「总体地点需求」和「原产候选需求」：前者综合食物压力、商品
短缺、人口/劳动力压力、发展度、控制力、市场接入度、既有等级、近期建造和等待时间；后者
综合原材料的供需、价格、利用率、剩余扩建空间、战略类别、原版基础成本和食物紧急加分。当前
版本不再提供单独的玩家权重。这一排序只在原产类别内部生效，不能越过「自动建造顺序」中
排在原产前面的建造类型。

## 配置与实现入口

- `policies/automation_rules.json`：节奏、阈值、分数与商品/建筑分组。
- `policies/building_catalog.json`：根据原版数据生成的玩家可管理建筑目录。
- `policies/video_building_priorities.json`：视频直评分和显式用户覆盖。
- `policies/templates.json`：内置预设，包括角色、允许/禁止建筑与优先商品。
- CMF 模组设置：同时建造上限、预算、国库储备、价格范围、自动建造顺序、收益要求、五个
  战略开关、安全规则、原产规则和性能设置。
- [`building_quality_priorities.md`](building_quality_priorities.md)：视频校准、升级继承和默认 0 规则。
- `src/eu5autobuild/catalog_builder.py`：读取原版建筑与科技，刷新目录、时代和升级继承值。
- `src/eu5autobuild/engine.py`：可测试的纯 Python 决策镜像。
- `src/eu5autobuild/generator.py`：生成实际 EU5 脚本、界面和本地化。
- `tests/test_automation_generator.py`：验证生成脚本中的节奏、预算、需求、补链与原产集成。

## 已知边界与验证

- 原版公开的五类原产扩建基础金币成本都是 100，本 Mod 已按该数据结算预算。
  `automation_rules.json` 中的 `rgo_budget_cost` 只是生成脚本所需的原版基础成本镜像；生成器
  会拒绝与原版五项价格不一致的值。原版 GUI 可以显示应用成本修正后的实时值，但当前脚本
  效果路径没有使用等价的可读 script value，因此预算结算暂不包含国家、地点等来源的动态
  原产成本修正。换言之，缺少的是修正后的实时值，不是原版基础成本数据。
- 本 Mod 会标记自己确认入队的项目，并在该地点不再有民用建造时清除标记。如果玩家随后
  在同一地点加入手动项目，该名额会保守地保持占用，直到当地民用建造全部结束。
- 静态测试校验真实 EU5 ID、生成文件、括号平衡和关键脚本接口。本机存在 `script_docs`
  时还会执行可选接口检查；缺少该目录不会阻止其他测试运行。
