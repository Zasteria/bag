# EU5 Advanced Auto Build

[English](README.md) | 简体中文

EU5 Advanced Auto Build 是一个非官方的《Europa Universalis V》Mod，通过区域发展策略模板规划自动建造。

当前版本：**0.9.1 Beta**。

整个 Mod——包括设计、代码、测试、生成的游戏脚本、界面、本地化和文档——均在 OpenAI GPT-5.6-Sol（Sol 5.6）模型协助下完成。

本 Mod 采用数据与生成器结合的混合架构：

- 策略规则以 JSON 数据定义。
- Python 生成器把规则转换为 EU5 的 `generic_actions`、`scripted_gui`、`on_action`、`scripted_effect`、`scripted_trigger`、`script_value`、GUI 和本地化文件。
- 社区模组框架的共享操作栏用于打开模板启停、范围、逐建筑优先级和诊断界面；全部内置与自定义模板共用的运行规则则集中在 CMF 模组设置中，同时不再覆盖其他 Mod 可能使用的面板标签类型。
- Python 单元测试校验策略结构、生成文件和自动建造的核心决策规则。

本项目是非官方玩家自制 Mod，与 Paradox Interactive 不存在隶属、认可或支持关系。

## 必需依赖

游戏运行时必须安装并启用社区模组框架 - 1.3 帕维亚。本 Mod 使用框架提供的共享操作栏入口与 CMF 模组设置；Mod 元数据中的依赖 ID 为 `community_mod_framework`，兼容版本范围为 `2.*`。

运行生成器和测试需要 Python 3.12 或更高版本。Python 代码只使用标准库，不需要安装第三方运行时依赖。

## 功能

- 向单个地点或整个省份应用发展策略。
- 按地区角色、产出商品、年度预算、价格区间和劳动力可用性决定建造优先级。
- 为每个策略配置允许与禁止的建筑。
- 配置国库储备，例如项目开工后至少保留 1000 金币。
- 控制自动建造是否可以建造或升级特殊建筑。
- 项目按食物安全、建筑材料瓶颈、人口必需品、军需品、上游投入品、市场供需和价格排列。普通生产建筑开工前，游戏还会检查实际成本和玩家选择的收益要求。
- 向内置预设和新建自定义模板应用视频校准的 0–10 建筑质量优先级；原版实际升级建筑继承前置建筑数值，没有视频评分、用户指定或可继承分数的建筑默认为 0。内置预设的显式允许列表可以覆盖全局 0，自定义模板中的 0 仍表示硬禁用。
- 当目标建筑所需劳动力阶层没有可用人口时阻止自动建造。
- 用 CMF 滑动条设置本 Mod 的额外同时建造数：0 代表总计最多 1 个在建项目，599 代表总计最多 600 个。只统计由本 Mod 确认开工且仍在建造的项目；手动建造、道路和其他 Mod 的项目不占此上限。本 Mod 每月只补足自己的剩余空位；每个地点同一时间最多安排 1 个项目，成功后等待 3 个月再检查。
- 全部内置预设与自定义模板共用一个国家级年度预算池；玩家在 CMF 模组设置中选择固定金额或月总收入 ×4/×6/×8，普通建筑按实际成本、原产按生成时从原版价格表校验的基础成本从该池扣除。
- 使用 CMF 滑动条调整国家国库储备：0–100,000 金币，每次 100。
- 拖动四种建造类型来设定先后顺序：升级建筑、扩建现有普通建筑、扩建原产资源、新建普通建筑。默认顺序为「升级 → 普通扩建 → 原产 → 新建」；系统会先尝试当前类型中所有能开工的项目，再查看下一类。
- 为普通生产建筑选择收益要求：收入大于 0、利润大于 0、收入年化回报率至少 5%，或利润年化回报率至少 5%。
- 预计食物储备耗尽或不高于 25% 时，先处理所有产出食物的项目，并允许普通食物建筑不检查所选收益要求。建造所需商品、战时军需品和阻塞战略建筑的上游原料这三个开关，只为匹配的建筑放宽收益要求。
- 同时建造上限、预算、国库储备、价格范围、特殊建筑、上游补建、劳动力/投入品保护、自动建造顺序、收益要求、紧急规则和原产规则只需在 CMF 模组设置中统一配置一次。
- 仅在原产容量利用率至少达到 75% 时扩建；原版调用失败不会消耗自动建造预算。原产没有独立的月度上限，只受本 Mod 剩余同时建造名额约束。
- 原产地点直接按地点整体需要、原材料短缺、价格、利用率、战略重要性和食物压力排序，不再提供额外排序权重；这一排序不会让原产越过排在前面的建造类型。
- 每月先把可安排地点分入二十个临时列表，2～21 日每天只评分一个列表，并让每个候选只进入唯一的「食物紧急状态／建造类型」阶段；22 日合并候选并完成入队。
- 普通候选因缺少投入品无法开工时，通过建造真正短缺的上游来源恢复供给。

视频校准种子的评分思路来自 Bilibili UP 主 [瘦扁扁](https://space.bilibili.com/456154809) 的 EU5 内容启发。

## 项目结构

```text
.metadata/
  metadata.json
  thumbnail.png
docs/en/
docs/zh-CN/
in_game/
policies/
README.zh-CN.md
src/eu5autobuild/
tests/
```

重要文件：

- `policies/templates.json`：单独维护的内置预设列表及规则。复制预设会生成独立的玩家模板，不会把预设名称加入原有六项自定义名称列表。
- `policies/building_catalog.json`：从原版生成的玩家可管理建筑目录，包含产出/投入商品、劳动力人口类型、时代和特殊建筑状态。
- `policies/video_building_priorities.json`：只保存视频直评分和显式用户覆盖。
- `policies/automation_rules.json`：定义节奏、市场阈值、需求分数、建筑质量优先级和商品/建筑分组。
- `docs/zh-CN/building_quality_priorities.md`：记录评分策略和视频校准建筑的字幕依据。
- `src/eu5autobuild/generator.py`：生成 EU5 Mod 文件。
- `src/eu5autobuild/catalog_builder.py`：刷新原版建筑目录，并沿真实 `obsolete` 升级链传播优先级。
- `src/eu5autobuild/rules.py`：校验并公开数据驱动的规则模式。
- `src/eu5autobuild/engine.py`：供测试使用的纯 Python 需求优先决策镜像。
- `docs/zh-CN/automation_rules.md`：记录分析依据和规则设计。
- `tests/`：包含策略数据、生成文件、建设决策和游戏脚本集成的单元测试。

## 策略数据

策略模板包括：

- 策略 ID 和本地化键
- 地区角色
- 优先商品
- 允许建筑
- 禁止建筑

玩家模板只保存身份、启用/暂停状态、应用范围和逐建筑 0–10 优先级；运行限制、额度、自动建造顺序、收益要求、紧急开关、原产开关与最低利用率属于国家级 CMF 模组设置，由全部模板共享。

建筑目录包括：

- 建筑 ID
- 产出商品
- 用于判断候选建筑是否缺少投入品的商品
- 劳动力人口类型
- 是否视为特殊建筑
- 从商品到上游来源建筑的可选显式映射

如果 EU5 的建筑 ID、商品 ID 或人口类型 ID 发生变化，请先运行目录生成器，再重新生成 Mod 文件。目录会排除事件专用占位建筑、阶层所有建筑，以及带有 `country_potential = { always = no }` 的定义；带国家、文化、宗教、外国、独特建筑或组织条件的建筑仍会保留，并继续受原版建造条件约束。

目录使用真实的 EU5 `building_types`、`goods` 和 `pop_types` ID。部分基础设施和原产辅助建筑在原版文件中没有直接声明 `produced = ...` 字段；这些建筑的 `output_goods` 表示其实际增产或支持的商品，使评分引擎仍能正确排列候选。

## 生成 Mod 文件

仓库不会写死某台电脑的 Steam 库路径。运行任一生成器前，请通过
`EU5_GAME_ROOT` 配置 EU5 安装根目录：

```powershell
$env:EU5_GAME_ROOT = "D:\path\to\SteamLibrary\steamapps\common\Europa Universalis V"
```

也可以为任一命令传入 `--game-root PATH`；显式参数优先于环境变量。
如果两者都没有提供，生成器会明确报错，不会猜测本机安装路径。

运行：

```bash
python3 -m src.eu5autobuild.catalog_builder
python3 -m src.eu5autobuild.generator
```

例如，不设置环境变量时：

```powershell
python -m src.eu5autobuild.catalog_builder --game-root "D:\path\to\Europa Universalis V"
python -m src.eu5autobuild.generator --game-root "D:\path\to\Europa Universalis V"
```

生成文件会写入：

```text
in_game/
.metadata/metadata.json
```

静态 Mod 图标存放于 `.metadata/thumbnail.png`，并由 `metadata.json` 引用。

使用 `--check` 可以在不写入文件的情况下验证生成内容：

```bash
python3 -m src.eu5autobuild.catalog_builder --check
python3 -m src.eu5autobuild.generator --check
```

## 运行测试

运行：

```bash
python3 -m unittest
```

测试覆盖：

- 必需策略字段
- 默认模板覆盖范围
- 建筑目录覆盖范围
- 生成文件集合
- 生成 EU5 脚本的括号平衡
- 本地化键覆盖
- 建造规则优先级
- 禁止与允许建筑行为
- 预算和现金储备阻止逻辑
- 价格区间阻止逻辑
- 劳动力和人口类型阻止逻辑
- 投入品短缺阻止逻辑
- 上游投入来源建造
- 可拖动的四类自动建造顺序及默认顺序
- 食物紧急优先及两个开关控制的收益例外
- 实际收入/利润/回报率校验、建造所需商品余量、预算预留和队列增长结算
- 引擎拒绝后在同类继续尝试，并只在同类耗尽后进入下一类
- 原产类别位置、共享名额内不限次数开工及类别内部地点排序
- 省份模板解耦
- 可选的本机 EU5 `building_types`、`goods` 和 `pop_types` 策略/目录 ID 校验

本机存在 EU5 `script_docs` 时会额外校验脚本接口名称；缺少该可选目录不会跳过其他真实游戏数据校验。

## 安装

可以直接把本目录作为本地 EU5 Mod 文件夹，或复制到启动器使用的《Europa Universalis V》本地 Mod 目录。

生成的 Mod 需要以下顶层结构：

```text
.metadata/
  metadata.json
  thumbnail.png
in_game/
```

复制或链接 Mod 文件夹后：

1. 在启动器中启用本 Mod。
2. 开始新游戏或载入现有存档。
3. 从社区模组框架的共享操作栏打开 EU5 Advanced Auto Build。
4. 在 CMF 模组设置中配置全部模板共享的同时建造上限、国库储备、预算、价格范围、自动建造顺序、收益要求、紧急开关、劳动力/投入品保护和原产规则。
5. 在本 Mod 窗口中配置每个模板的启用/暂停状态、应用范围和逐建筑 0–10 优先级（自定义模板中 0 表示禁用）。
6. 把模板应用到地点、省份或地区；使用 `清除策略` 移除绑定。
7. 等待到下一个每月 22 日，让系统完成首轮候选合并与入队；随后可查看运行诊断和建造队列。

## 已知限制

- EU5 没有可供本 Mod 永久保存自定义模板名称的接口。模板设置仍会保留，但重新读档后，自定义名称会恢复为默认值。
- 原版价格表公开的五类原产扩建基础金币成本都是 100。生成器会直接读取这五项，并校验生成脚本使用的 `automation_rules.json` 镜像值；这个值不是独立估算，也不是可调的平衡参数。本 Mod 已按原版基础成本结算预算。当前脚本效果路径不能读取应用国家、地点等修正后的实时原产成本，因此预算结算暂不包含这些动态修正。

## 可能的后续功能

- **自动进口短缺的投入品**：目前没有找到适合本 Mod 稳定调用的通用目标接口，因此尚未实现。
- **生产方式切换**：EU5 原版已经提供全局自动化和逐建筑锁定，本 Mod 不重复实现常规切换。
- **自动授予城镇权利**：技术上可以实现，但当前版本尚未包含；需要先完成规则、选址和费用策略研究。
