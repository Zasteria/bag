# V3 TAG 与文化选择器的设计方针和逻辑

本文依据 Victoria 3 Cheat Menu Pro 中现有的 `sakuya_tag_index_alpha.gui`、`sakuya_culture_index.gui` 及其配套 scripted GUI，总结其设计方针，并说明如何把这些原则转换为 Europa Universalis V 的国家、文化和宗教选择工具。这里描述的是已经在文件中看到的结构，不把不同 Jomini 游戏的接口混为一谈。

## 一、选择器首先是一套工作流程

V3 选择器的核心并不是把全部 TAG 或文化塞进一个窗口，而是把“找到对象、辨认对象、选择对象、确认状态、清除状态”组织成一条连续流程。窗口本身是独立的可移动界面，拥有明确的标题、关闭入口和固定内容区域。主体不是平均切成许多按钮，而是建立主次关系：主要空间交给筛选和结果列表，较小区域承担当前选择、说明或确认功能。玩家打开窗口后，注意力首先落在搜索或筛选区域，然后自然移动到结果，再通过颜色和状态判断选择是否成功。

这种结构的重要性在于对象数量可能很大。国家、文化等数据库不是十几个固定命令，而是需要检索的数据集。若直接把所有项目平铺，屏幕密度、滚动距离、加载成本和维护成本会同时失控。V3 虽然由于自身实现条件仍包含大量生成条目，但它在可见层面没有把数据库当作一面无结构的按钮墙，而是通过模式、字母、地域、存在状态等筛选，将玩家当前需要处理的集合缩小。真正应当继承的是这种信息架构，而不是机械复制条目生成方式。

## 二、窗口状态、筛选状态与对象标记必须分离

V3 方案使用多组 UI 变量管理界面状态。例如窗口是否打开、当前语言或索引模式、字母筛选、地域筛选、列表中临时高亮的对象、已经确认的对象，分别由不同变量表达。这样做可以避免一个变量同时承担多种语义。关闭窗口不等于删除游戏对象上的标记；改变字母筛选也不应清除当前选择；临时浏览某个对象与最终把它设为修改目标，也可以是两个不同阶段。

从设计上看，至少要区分四层状态。第一层是窗口状态，只控制显示和输入。第二层是检索状态，包括搜索文本、排序键和分类过滤。第三层是界面选择状态，用来决定哪一行、哪个筛选按钮处于按下或高亮状态。第四层是游戏逻辑标记，它真正告诉后续作弊功能应当操作哪个国家、文化或宗教。前两层属于浏览过程，后两层属于选择结果。把这四层混写，会出现关闭窗口后目标丢失、过滤后按钮失色、列表刷新后标记错位等问题。

EU5 重写方案保留这种分离，但利用原版统计系统进一步简化。国家列表使用 `CountriesListView.GetCountriesSortSearch` 和 `CountriesListView.GetCountriesListView`；文化列表使用 `CulturesLedger.GetCultureItemsSortSearch` 和 `CulturesLedger.GetCultures`；宗教列表使用 `ReligionsLedger.GetReligionsSortSearch` 和 `ReligionsLedger.GetReligions`。搜索文本、排序和结果集合由原版 `filtered_sorted_list` 管理，不再自行制造字母分页，也不需要为每个数据库对象创建一段 GUI。模组只负责窗口、点击行为和标记状态。

## 三、按钮变色不是装饰，而是状态反馈

V3 选择器中的按钮至少表达普通、悬停、激活和不可用等状态。筛选按钮激活时，会叠加 `big_header_pattern.dds`，并使用约 `{ 0.58 0.18 0.25 }` 的红色调。结果行被选中时也使用相同视觉语言。红色纹理不是随机装饰，而是统一表达“这个条件或对象正在生效”。不可用项目则使用更灰暗的遮罩，使其与已经选择的红色状态明显区分。

按钮仍然需要悬停反馈。悬停表示“鼠标当前可与此对象交互”，激活表示“该对象已经成为当前目标”，两者不能合并。若只保留激活色，玩家在点击前无法判断可交互区域；若只保留悬停色，鼠标移开后又无法确认结果。EU5 新列表因此使用原版 `scroll_card_button` 的普通、悬停、按下帧，同时在对象已被标记时叠加 V3 同源的红色纹理。鼠标移动会触发清楚的原版按钮反馈，选中后则持续显示按下状态和红色底纹。二者职责不同，也可以同时存在。

筛选按钮的颜色同样必须由真实状态驱动，而不能在点击后盲目切换一个与逻辑无关的布尔值。V3 中筛选按钮的红色覆盖层通过 `GetVariableSystem.HasValue` 或 `Exists` 判断当前模式。结果行则按具体 TAG 或文化键判断。EU5 重写不再保存成千上万个字符串键，而是直接检查结果对象作用域上的唯一标记变量。国家行检查 `sakuya_get_TAG_choosen`，文化行检查 `sakuya_selected_culture`，宗教行检查 `sakuya_selected_religion`。因此颜色与后续脚本实际使用的对象状态一致，不会出现界面显示选中、脚本却找不到目标的双重真相。

## 四、唯一标记系统的职责

选择器服务于后续修改功能，所以每一类别只能存在一个当前目标。V3 的基本思路是在选择新对象时清除旧对象，再设置新对象，并为清除操作提供独立入口。EU5 中也必须保持这一不变量。国家选择时遍历带有旧国家标记的对象，移除 `sakuya_marked_country` 和 `sakuya_get_TAG_choosen`，随后在当前国家上同时写入两者，以兼容模组中已经消费这些变量的功能。文化和宗教分别清除同类对象上的旧标记，再在当前对象上设置各自变量。国家、文化、宗教互不干扰。

行左键执行“选择此对象”，行右键执行“仅当此对象已被标记时取消”。右侧“清除选择”则从玩家国家作用域发起，清除该类别中任何已存在的标记。这样既保留局部取消，也提供全局复位。`is_valid` 同时承担按钮可用性判断：未选中的行允许左键标记；已选中的行允许右键取消；没有任何目标时，清除按钮禁用。按钮状态因此直接反映 scripted GUI 能否执行。

为了让右侧状态区与对象标记同步，标记动作还会在玩家国家上保存当前对象的作用域变量。这个变量只用于证明“当前类别已有目标”以及未来扩展预览，不替代对象自身标记。对象变量是后续游戏逻辑的权威来源，玩家变量是窗口状态的索引。清除或取消时两者必须一起移除，避免右侧仍显示“已选择”而实际目标已经不存在。

## 五、EU5 中的适配边界

借鉴 V3 不等于复制 V3 文件，也不等于覆盖 EU5 原版统计 GUI。新方案保留三个独立模组窗口，入口仍由模组自己的按钮组合点击控制。窗口内部调用原版公开使用的数据管理器和共享控件，但不创建 `countries_list_view.gui`、`cultures_ledger.gui` 或 `religions_ledger.gui` 的覆盖文件。原版统计页面继续保持原状，模组只是复用同一搜索、排序和数据模型。

国家窗口显示旗帜、名称、等级、人口、宗教和文化；文化窗口显示名称、人口、语言、影响力和主导国家；宗教窗口显示图标、名称、宗教组、人口和国家数。这些字段全部来自对应原版统计页已使用的接口。列标题和排序行为也使用原版 sort key，不制造新的排序参数。

最终设计原则可以概括为：让原版数据系统负责数据，让独立窗口负责工作流程，让 scripted GUI 负责唯一标记，让颜色只表达真实状态。搜索必须先于罗列，状态必须先于装饰，标记必须只有一个权威来源。只有这三层边界清楚，选择器才能在数据库继续扩充时仍保持可用、可维护，并与模组后续功能稳定连接。
