# 自动建造规则说明

[English](../en/automation_rules.md) | 简体中文

## 目标

原版经济自动化更擅长寻找单个高利润建筑，但不一定会先补足食物、建造所需商品、人口必需品和军需品。本 Mod 会先判断市场和产业链最缺什么，再从符合模板、预算、劳动力和游戏建造条件的项目中选择。普通建筑开工前，还会读取游戏给出的预测月收入、预测月利润和建造成本，并按玩家选择的收益要求做最后检查。

## 系统会参考哪些信息

本 Mod 使用游戏当前提供的数据来判断需求和可行性：

- 市场食物储备、月度食物结余，以及食物是否即将耗尽。
- 商品的市场供应、需求和价格，特别是建造所需商品、人口必需品与军需品。
- 建筑的投入品、产出品、建造成本、预测月收入和预测月利润。
- 地点现有建筑、民用建造、冷却状态，以及当前和预计可用劳动力。
- 原产的扩建上限、当前利用率、市场需求和游戏自身的扩建条件。

本 Mod 不会绕过游戏原本的解锁、建造和地点限制。详细的数据文件与接口说明见文末的「开发者说明」。

## 每月怎样选择项目

自动建造每月分几步完成：

1. 月初同步 CMF 模组设置，更新地点冷却，并统计本 Mod 仍在建造的项目。手动建造、道路和其他 Mod 的项目不占用本 Mod 的同时建造名额。
2. 每年 1 月按固定金额或月总收入的 4、6、8 倍确定年度预算。所有模板共用这笔预算。
3. 2～21 日分批检查已应用模板的地点，避免在同一天处理全国。玩家可以设置每天最多详细检查多少个地点。
4. 每个地点先按模板和安全条件找出可建项目。「供需规划」按「规划候选数」保留每种普通建造类型中规划分最高的前 3～30 个；「预测利润择优」按「利润候选数」保留前 3～30 个，以便比较游戏预测月利润。原产单独按自身规则判断。
5. 22 日统一安排项目。食物紧急项目最先处理，随后按玩家设置的「自动建造顺序」依次检查升级、普通扩建、原产扩建和新建。
6. 某个项目不能开工时，系统会继续寻找同类项目；当前类型确实没有可建项目后，才进入下一类。
7. 项目真正进入民用建造队列后，系统才扣除预算、占用同时建造名额，并让该地点进入 3 个月冷却。原产与普通建筑共用名额，没有单独的月度上限。
8. 开启「缺少投入品时自动补建上游」后，计划中的建筑因缺少原料而无法开工时，系统会尝试建设模板允许且能缓解短缺的上游建筑。

玩家设置的是基础 1 项之外的额外同时建造数：0 代表本 Mod 最多同时进行 1 项，599 代表最多 600 项。系统每月只补足本 Mod 自己的剩余空位；每个地点同一时间最多安排 1 个项目。

## 项目必须满足的条件

价格高并不代表项目一定会盲目开工。候选项目还必须满足以下条件：

- 建筑质量优先级必须高于 0，除非该建筑被风味模板显式列入允许列表。自定义模板中的 0 始终表示禁用。
- 建筑在模板允许范围内且不在禁止列表中；特殊建筑需要明确许可。
- 地点没有正在进行的民用建造，且 3 个月冷却已经结束。
- 开启劳动力保护时，预计可用劳动力必须能在设置期限内填补新增岗位。
- 开启投入品保护时，候选所需工业投入品的供给不得低于需求的 75%。
- 产出商品价格低于设定最低价格百分比的过剩商品将停止扩建；高价格表示短缺，会获得排序加分。
- 普通生产建筑必须达到设定的游戏预测收益要求，处于战略豁免状态时除外；没有产出的基础设施不受这项收益校验限制。
- 本轮已经安排的其他项目也会占用建造所需商品；合计需求不能高到可能让建造部门停工。每种建造所需商品的市场价格也不得高于默认价格的 150%。
- 普通建筑的建造成本必须在剩余年度预算内，付款后还要满足国库储备。原产按原版基础成本 100 计算预算。项目真正进入建造队列后才会结算。

## 需求评分

以下分数决定「供需规划」中的先后顺序。生存需求和产业链瓶颈的分数远高于普通价格加分，
因此食物与关键原料短缺时，不会轻易被奢侈品的高价信号盖过。
| 信号 | 分数 |
| --- | ---: |
| 市场预计食物储备耗尽 | +12000 |
| 食物储备不高于 25% | +9000 |
| 食物储备不高于 50% | +6000 |
| 月度食物结余为负 | +4500 |
| 建造所需商品供给/需求不高于 65% | +5000 |
| 建造所需商品供给/需求不高于 90%，或价格高于 125% | +3000 |
| 人口必需品严重/一般短缺 | +2800 / +1400 |
| 军需品严重/一般短缺 | +3500 / +1200 |
| 战时军需额外加分 | +1800 |
| 短缺的上游来源 | +3200 |
| 策略优先商品 | 首项 +600，随后每项 -20 |
| 视频校准建筑质量 | 0～10，每点 +50；可继承前置建筑分数，否则默认为 0 |
| 建筑角色匹配 | +300 |
| 投入品严重不足 | -3000 |
| 同类建筑既有等级 | 每级 -25 |

初选阶段用供需、价格、建筑优先级和劳动力等信息计算规划分。普通建筑进入最后检查后，
系统才读取游戏预测月收入、预测月利润和建造成本。这样既能优先处理食物与产业链瓶颈，
也能在市场稳定时用价格、模板优先级和饱和度区分同类项目。


## 建造决策策略

玩家选择的收益指标是开工资格，不是排序指令。建筑达到「收入、利润、收入回报率或利润
回报率」要求，只代表它可以继续参与比较，不代表它会优先于其他合格项目。食物紧急状态和
「自动建造顺序」确定当前层级与建造类型后，CMF 模组设置提供两种普通建筑决策策略：

- **供需规划**：根据市场短缺、战略需求、配方效率、本地原料、商品价格和劳动力风险综合安排建造，侧重产业链完整与长期供需稳定。模板的 0～10 建筑优先级直接计入规划分。粗筛与最终排序使用同一规划分；「规划候选数」决定每个地点和普通建造类型保留多少个高分项目，第 2 名以后用于更高分项目未通过后续检查时回退。该上限不能保证其后的项目一定不会被漏掉。
- **预测利润择优**：先筛选符合模板和安全条件的候选，再按照游戏预测月利润择优建造。利润相近时，0～10 建筑优先级会产生软性影响：`排序值 = 预测月利润 + max(|预测月利润|, 1) × 优先级 × 0.01`。每高 1 级约增加 1% 相对排序权重，10 级最多约 10%。该策略只在每个地点、当前普通建造类型预筛选出的「利润候选数」（3～30）个候选中择优，并受食物紧急层和「自动建造顺序」约束，因此不代表全局绝对最高利润。

预测利润择优策略在正式开工前会重新校验预测收益、预算、国库储备、建材储备、劳动力及原版建造条件。该模式不会破坏食物危机优先原则，也不会改变「自动建造顺序」或原产排序规则。

「规划候选数」和「利润候选数」位于 CMF 模组设置的「性能优化 → 高级设置」，分别只在「供需规划」和「预测利润择优」下显示并生效。规划候选数越高，越不容易在前几名检查失败时漏掉后续可行项目；利润候选数越高，越不容易因粗筛分与最终利润指标不同而提前淘汰真实高利润项目。两者都会增加后续检查次数，但互不影响。性能预设会同步设置两者：保守为 5 / 15、平衡为 4 / 12、效率优先为 3 / 10（规划 / 利润）；手动修改任一候选数后，性能预设会切换为「自定义」。

## 自动建造顺序、收益要求与紧急规则

「自动建造顺序」是全部模板共享、可自由拖动排序的四项列表：

1. 升级建筑
2. 扩建现有普通建筑
3. 扩建原产
4. 新建普通建筑

评分只决定当前类型内部的先后，不能让排在后面的类型提前。某个项目不能开工时，系统会继续寻找同类项目，当前类型耗尽后才进入下一类。

普通生产建筑有四种收益要求：

| 设置 | 开工要求 |
| --- | --- |
| 收入 | 游戏预测月收入大于 0 |
| 利润 | 游戏预测月利润大于 0 |
| 收入回报率 | 游戏预测月收入不低于 `实际成本 × 5% ÷ 12` |
| 利润回报率 | 游戏预测月利润不低于 `实际成本 × 5% ÷ 12` |

五个战略开关彼此独立：

| 开关条件 | 是否优先处理 | 哪些建筑可放宽收益要求 |
| --- | --- | --- |
| 市场预计食物储备耗尽 | 是 | 匹配的普通食物建筑 |
| 食物储备不高于 25% | 是 | 匹配的普通食物建筑 |
| 核心建造所需商品供应低于需求的 65% | 否 | 生产相应商品的建筑 |
| 战争期间军需品供应低于需求的 65% | 否 | 生产相应军需品的建筑 |
| 上游原料低于需求的 65%，并阻塞已开启的战略建筑 | 否 | 生产相应上游原料的建筑 |

两个食物开关既会优先处理食物项目，也会为匹配的普通建筑放宽收益要求。其他三个开关只
放宽收益要求。所有开关都不会绕过年度预算、国库储备、劳动力/投入品保护、建造所需商品、
游戏自身的建造条件、地点队列可用性或本 Mod 的同时建造上限。

## 原产规则

原产只在以下条件同时满足时尝试扩建：

- 尚未完全扩建，且当前岗位利用率达到玩家设定的门槛（可在 0%～100% 范围内按 5% 调整，默认 75%），避免继续扩建缺少工人的原产。
- 原材料属于短缺的食物、建造所需商品，或当前策略的优先商品。
- 国库储备和共享年度预算能够覆盖原版基础成本 100。

只有原产扩建真正进入民用建造队列后，系统才会占用名额、设置冷却并扣除预算。游戏拒绝
扩建时不会扣款。

原产地点会综合比较食物压力、商品短缺、劳动力、发展度、控制力、市场接入度、原料价格、
利用率和剩余扩建空间。这个排序只在原产类别内部生效，不能越过「自动建造顺序」中排在
原产前面的建造类型。

## 玩家设置入口

- 模板界面：设置模板启停、应用范围和每种建筑的 0～10 优先级。
- CMF 模组设置：设置同时建造上限、预算、国库储备、价格范围、建造决策策略、自动建造
  顺序、收益要求、战略开关、安全规则、原产规则和性能选项。
- 建造报告：查看最近一次月度检查、实际开工项目和未通过原因。
- [`building_quality_priorities.md`](building_quality_priorities.md)：查看推荐建筑优先级及其依据。

## 开发者说明

- `policies/automation_rules.json`：节奏、阈值、分数与商品/建筑分组。
- `policies/building_catalog.json`：根据原版数据生成的玩家可管理建筑目录。
- `policies/video_building_priorities.json`：视频直评分和显式用户覆盖。
- `policies/templates.json`：风味模板，包括角色、允许/禁止建筑与优先商品。
- `src/eu5autobuild/catalog_builder.py`：读取原版建筑与科技，刷新目录、时代和升级继承值。
- `src/eu5autobuild/engine.py`：可测试的纯 Python 决策镜像。
- `src/eu5autobuild/generator.py`：生成实际 EU5 脚本、界面和本地化。
- `tests/test_automation_generator.py`：验证生成脚本中的节奏、预算、需求、补链与原产集成。

## 已知限制与测试

- 原版五类原产扩建的基础金币成本都是 100，本 Mod 按这个基础成本结算预算。国家、地点等
  带来的动态成本修正暂时不会反映到本 Mod 的预算中。
- 本 Mod 会标记自己确认入队的项目，并在该地点不再有民用建造时清除标记。如果玩家随后
  在同一地点加入手动项目，该名额会保守地保持占用，直到当地民用建造全部结束。
- 静态测试校验真实 EU5 ID、生成文件、括号平衡和关键脚本接口。本机存在 `script_docs`
  时还会执行可选接口检查；缺少该目录不会阻止其他测试运行。
