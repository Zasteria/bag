# EU5 Advanced Auto Build

[English](README.md) | 简体中文

EU5 Advanced Auto Build 是一个非官方的《Europa Universalis V》（欧陆风云5）Mod，旨在通过区域发展模板为玩家提供更智能、可定制的自动建造规划。

当前版本：**0.9.4 Beta**。

整个 Mod——包括架构设计、代码实现、测试套件、生成的游戏脚本、界面布局、多语言本地化和文档——均在 OpenAI GPT-5.6-Sol（Sol 5.6）模型协助下完成。

玩家可以通过模板灵活指定不同地点允许建造的建筑类型及优先级，并在 CMF 模组设置中统一调控全国预算、劳动力保护、建造安全与决策策略。每次月度自动建造的执行详情均可在游戏内的「建造报告」中直观查看。

本项目是非官方玩家自制 Mod，与 Paradox Interactive 不存在隶属、认可或支持关系。

## 必需依赖

游戏运行前必须安装并启用「社区模组框架 - 1.3 帕维亚」（Community Mod Framework / CMF）。本 Mod 依赖该框架提供的操作栏统一入口与 CMF 模组设置界面；Mod 元数据中的依赖 ID 为 `community_mod_framework`，兼容版本为 `2.*`。

运行生成脚本与测试套件需要 Python 3.12 或更高版本。Python 脚本仅使用标准库，无需安装任何第三方运行时依赖。

## 核心功能

- **灵活的模板与范围分配**：支持将区域发展策略模板应用至单个地点、整个省份或整个地区；可自由配置各模板允许或禁止建造的建筑列表。
- **智能需求与优先级评估**：综合考量地区定位、产出商品、年度预算、市场物价与劳动力供给；建造需求按食物安全、建材瓶颈、人口必需品、军需品、上游原料、市场供需及价格梯级综合排序。
- **游戏引擎收益校验**：在普通生产建筑开工前，系统会自动读取游戏预测的月收入、月利润及实际建造成本，严格校验设定的经济回报门槛。可选择要求月收入 > 0、月利润 > 0、收入年化回报率 ≥ 5%，或利润年化回报率 ≥ 5%（约 20 年回本）。
- **双重决策模式**：
  - **供需规划**：侧重市场供需调控、产业链闭环与劳动力安全，提供可在 3～30 范围内配置的规划候选池。
  - **预测利润择优**：在满足安全条件的前提下，按游戏预测的月利润择优开工，并以模板建筑优先级（0–10）作为相近利润下的软性决胜分（每分约 1% 权重，最高约 10%）。提供专属的 3～30 利润候选池配置。
- **建筑优先级**：风味模板与新建推荐模板预设了 0–10 的建筑优先级；空白模板默认全部禁用。升级链中的后续高级建筑会自动继承前置建筑的优先级；无评分且无法继承的建筑默认为 0。风味模板可根据定位特殊启用个别 0 分建筑，而在自定义模板中 0 始终代表完全禁用。
- **共享年度预算与国库安全**：所有预设与自定义模板共享全国统一的年度预算池，支持设定固定金额或按月总收入的 4、6、8 倍动态核定；可设置最低国库储备金（范围 0–100,000 金币，步长 100，如开工后必须保留至少 1,000 金币，避免国库见底）。普通建筑按游戏实际建造成本扣除，原产扩建按 100 金币的基础成本结算。
- **劳动力与投入品保护**：当目标建筑所需阶层的可用劳动力不足时，自动拦截建造，避免产生无工人运作的闲置建筑；开启「短缺时自动补建上游」后，下游产业因原料短缺无法开工时，系统可转为补建模板允许且确实短缺的上游产业。
- **特殊建筑开关**：可在 CMF 模组设置中决定是否允许自动建造或升级特殊建筑；开启后仍须满足游戏原版的建造条件。
- **自定义建造类型顺序**：支持自由调整四类建造行为的先后执行顺序（建筑升级、普通建筑扩建、原产资源点 RGO 扩建、新建普通建筑，默认顺序为「升级 → 扩建 → 原产 → 新建」）；系统会优先穷尽当前类型中所有可开工项目，再进入下一类型。
- **危机紧急豁免机制**：当市场食物预计耗尽或储备 ≤ 25% 时，系统优先调度产粮项目并豁免收益检查；建材严重短缺、战时军需及战略上游断供时，对应的生产建筑也可特例放宽收益限制。
- **原产地（RGO）合理扩建**：原产最低岗位利用率门槛可在 0–100% 范围内按 5% 调整，默认值为 75%，用于避免盲目扩建缺工的原产点；候选会综合考量原料短缺、物价、当前利用率、战略需求与食物压力，并且只在原产类型内部排序。原产不设独立月度上限，与普通建筑共享总名额；若游戏原版逻辑拒绝扩建，则不会扣除预算。
- **无侵入并发控制与冷却**：可在 CMF 设置中拖动滑动条配置本 Mod 的额外同时建造数（0 代表最多同时 1 个项目，599 代表总计最多 600 个），玩家手动建造、修路及其他 Mod 的项目不占此名额；每个地点同一时间最多开工 1 个项目，开工后进入 3 个月冷却。
- **分批扫描平滑性能**：每月 2～21 日分批扫描已分配模板的地点，22 日集中结算并开工，避免单日集中扫描造成游戏卡顿；内置多种性能预设，可灵活调节每日扫描规模与单轮最大开工数。
- **游戏内建造报告**：提供直观的「建造报告」面板，随时查看最近一次月度建造的开工项目、实际建造成本、预测收益以及候选项目的具体未开工原因。
- **全国共享设置**：同时建造上限、预算、国库储备、价格区间、决策策略、特殊建筑、上游补建、劳动力与投入品保护、建造顺序、收益门槛、紧急规则及原产规则均在 CMF 模组设置中统一配置，由所有模板共享。

建筑评分参考了 Bilibili UP 主 [瘦扁扁](https://space.bilibili.com/456154809) 的 EU5 评测与攻略。

## 开发者：项目结构

```text
.metadata/
  metadata.json
  thumbnail.png
docs/en/
docs/zh-CN/
in_game/
policies/
README.zh-CN.md
src/eu5autobuild/
tests/
```

重要文件：

- `policies/templates.json`：单独维护的风味模板列表及规则。复制预设会生成独立的玩家模板，不会把预设名称加入原有六项自定义名称列表。
- `policies/building_catalog.json`：从原版生成的玩家可管理建筑目录，包含产出/投入商品、劳动力人口类型、时代和特殊建筑状态。
- `policies/video_building_priorities.json`：只保存视频直评分和显式用户覆盖。
- `policies/automation_rules.json`：定义节奏、市场阈值、需求分数、建筑质量优先级和商品/建筑分组。
- `docs/zh-CN/building_quality_priorities.md`：记录评分策略和视频校准建筑的字幕依据。
- `src/eu5autobuild/generator.py`：生成 EU5 Mod 文件。
- `localization/translations/*.json`：保存巴西葡萄牙语、法语、德语、日语、韩语、波兰语、俄语、西班牙语和土耳其语译文，并同时记录翻译时对应的中英文源文。
- `src/eu5autobuild/catalog_builder.py`：刷新原版建筑目录，并沿真实 `obsolete` 升级链传播优先级。
- `src/eu5autobuild/rules.py`：校验并公开数据驱动的规则模式。
- `src/eu5autobuild/engine.py`：供测试使用的纯 Python 需求优先决策镜像。
- `docs/zh-CN/automation_rules.md`：记录分析依据和规则设计。
- `tests/`：包含策略数据、生成文件、建设决策和游戏脚本集成的单元测试。

生成上述九种语言时，只有翻译目录中记录的中文、英文源文仍与当前版本同时匹配，生成器才采用该译文。新增键或任一源文发生变化时，会直接输出当前英文，因此功能更新不必立即补译，也不会静默沿用过期译文。运行 `python3 -m src.eu5autobuild.generator --check` 会输出各语言已翻译、缺失、源文变化和废弃条目的非阻塞汇总。现有英文和简体中文本地化仍是源数据，不会被这套合并逻辑改写。

运行 `python3 -m src.eu5autobuild.localization_check` 可在不安装 EU5 的情况下校验翻译 JSON、源文状态、EU5 标记、UTF-8 BOM/CRLF 输出，以及 `in_game` 与 `main_menu` 本地化是否逐字节一致。GitHub Actions 会对涉及本地化的拉取请求运行同一检查。缺失、源文变化和废弃译文只产生警告，因为生成结果会按设计回退英文；JSON 结构错误、标记损坏、生成文件过期或两个游戏层不一致会使检查失败。翻译 JSON 在所有平台固定使用 LF，生成的 EU5 本地化固定使用 CRLF。

## 开发者：策略数据

策略模板包括：

- 策略 ID 和本地化键
- 地区角色
- 优先商品
- 允许建筑
- 禁止建筑

玩家模板只保存身份、启用/暂停状态、应用范围和逐建筑 0–10 优先级；运行限制、额度、自动建造顺序、收益要求、紧急开关、原产开关与最低利用率属于国家级 CMF 模组设置，由全部模板共享。

建筑目录包括：

- 建筑 ID
- 产出商品
- 用于判断候选建筑是否缺少投入品的商品
- 劳动力人口类型
- 是否视为特殊建筑
- 从商品到上游来源建筑的可选显式映射

如果 EU5 的建筑 ID、商品 ID 或人口类型 ID 发生变化，请先运行目录生成器，再重新生成 Mod 文件。目录会排除事件专用占位建筑、阶层所有建筑，以及带有 `country_potential = { always = no }` 的定义；带国家、文化、宗教、外国、独特建筑或组织条件的建筑仍会保留，并继续受原版建造条件约束。

目录使用真实的 EU5 `building_types`、`goods` 和 `pop_types` ID。部分基础设施和原产辅助建筑在原版文件中没有直接声明 `produced = ...` 字段；这些建筑的 `output_goods` 表示其实际增产或支持的商品，使评分引擎仍能正确排列候选。

## 开发者：生成 Mod 文件

仓库不会写死某台电脑的 Steam 库路径。运行任一生成器前，请通过 `EU5_GAME_ROOT` 配置 EU5 安装根目录：

```powershell
$env:EU5_GAME_ROOT = "D:\path\to\SteamLibrary\steamapps\common\Europa Universalis V"
```

也可以为任一命令传入 `--game-root PATH`；显式参数优先于环境变量。如果两者都没有提供，生成器会明确报错，不会猜测本机安装路径。

运行：

```bash
python3 -m src.eu5autobuild.catalog_builder
python3 -m src.eu5autobuild.generator
```

例如，不设置环境变量时：

```powershell
python -m src.eu5autobuild.catalog_builder --game-root "D:\path\to\Europa Universalis V"
python -m src.eu5autobuild.generator --game-root "D:\path\to\Europa Universalis V"
```

生成文件会写入：

```text
.metadata/*.json
in_game/
main_menu/localization/
```

静态 Mod 图标存放于 `.metadata/thumbnail.png`，并由 `metadata.json` 引用。

使用 `--check` 可以在不写入文件的情况下验证生成内容：

```bash
python3 -m src.eu5autobuild.catalog_builder --check
python3 -m src.eu5autobuild.generator --check
```

本机存在 EU5 `script_docs` 时会额外校验脚本接口名称；缺少该可选目录不会跳过其他真实游戏数据校验。

## 安装与使用

可以直接把本仓库目录作为本地 EU5 Mod 文件夹，或复制到启动器使用的《Europa Universalis V》本地 Mod 目录。

生成的 Mod 需要以下顶层结构：

```text
.metadata/
  metadata.json
  thumbnail.png
in_game/
```

复制或链接 Mod 文件夹后：

1. 在游戏启动器中启用本 Mod 与 Community Mod Framework。
2. 开始新游戏或载入现有存档。
3. 从社区模组框架（CMF）的共享操作栏打开 EU5 Advanced Auto Build 面板。
4. 在 CMF 模组设置中配置所有模板共享的全局规则（同时建造上限、最低国库储备、预算模式、价格区间、决策策略、建造顺序、收益门槛、紧急开关、特殊建筑与上游补建开关、劳动力与投入品保护，以及原产规则）。
5. 新建空白模板或使用推荐优先级模板，配置启用/暂停状态、应用范围以及各建筑的 0–10 优先级。点击增减 0.1、Ctrl+点击增减 0.5、Shift+点击增减 1.0；「当前列表全部清零」仅清零当前筛选下可见的建筑。
6. 将模板应用到地点、省份或地区；需要解绑时使用「清除策略」。
7. 等待游戏推进至下一个月度 22 日执行自动建造；随后可在「建造报告」中查看具体开工项目与未开工原因。

## 已知限制

- EU5 原版目前缺少能够跨存档持久化保存自定义模板名称的脚本接口。模板内的所有规则与地点绑定均会完整保存，但重新读档后自定义模板名称会恢复为默认名称。
- 原版原产扩建的基础成本统一为 100 金币，本 Mod 目前按该基础成本扣减预算，国家或地点层面的动态建造成本修正暂未计入原产预算结算中。

## 待探索的后续功能

- **自动进口短缺原料**：目前尚未找到稳定且通用的游戏内部接口，暂未实装。
- **生产方式自动切换**：EU5 原版已自带全局自动化与逐建筑锁定功能，本 Mod 目前没有更好的算法和实现接口，暂不重复制作。
- **自动授予城镇权利**：本 Mod 目前不会自动授予城镇权利。
