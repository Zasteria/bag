# Второй режим плана: специализация

**Его заказ, 2026-09-07, дословно:** «Это будет максимально специализированный
режим заполнения. Тут равномерность и лимиты не значат ничего. Только
максимально эффективная выжимка из провинции всех её бонусов. Если провинция
идеально подходит для ремесленных прав — все города в ней будут ремесленных прав
+ лучший по бонусу РГО домики в свободные ячейки. Никаких правил, только выгода.
Сделай отдельную кнопку для такого плана в меню мода. Но в остальном этот план
должен подчиняться всё тем же правилам мода технического характера — выбор
земли, сохранение в слот, кол-во домиков на село и город и т.п.»

Кнопка — «Специализация» на вкладке «Расчёты» страницы мода. Считает и открывает
окно плана.

## Разница ровно в двух местах

Конвейер общий: `_collect_candidates` → `_plan_prepare` → `_plan_score` →
грамоты → `_plan_set_quota` → заполнение → `_plan_rank` → `_edit_save`.

| | равномерный план | специализация |
| --- | --- | --- |
| грамоты | `_plan_grant_pass`, город за городом, лестница уровней | `_plan_spec_rights`, провинция целиком |
| комнаты | `_plan_allocate`, круг по товарам | `_plan_spec_fill`, круг по локациям |

**Грамоты.** Провинция считает **среднюю** оценку каждой грамоты (`_rq<k>`) по
своим городам, берёт лучшую и отдаёт её каждому своему городу. Средняя, а не
сумма: сумма выбирала бы грамоту по числу городов. Начальное лучшее — `-1`, а не
ноль: `_rq<k>` честно равен нулю там, где сырья нет вовсе, и сравнение с нулём не
дало бы такой грамоте ни одного города (это уже стоило прогона 2026-09-03).

**Комнаты.** Вопрос повёрнут наоборот. Обычная раздача ходит по товарам («где моё
лучшее место?»), эта — по локациям («кто здесь платит больше всех?»). Поэтому
квот, ступеней и полос тут нет: сравнивать их не с чем, сравниваются сами выгоды
в этой самой локации. Начальное лучшее — снова `-1`: товар с нулевой выгодой
занимает комнату, если лучше него тут никого нет, потому что пустая комната — это
не специализация, а неиспользованная земля.

## Что осталось общим — его же оговорка

Выбор земли и все пять способов её набрать; пометки город/село; лимиты домиков на
город и на село; три слота сохранения; редактор поверх и «Показать изменения»;
«Расширить». Пометка **«не нужен» соблюдается**: это стоячее указание игрока, а
не правило равномерности, и «никаких правил» его не отменяет. Пометка
**«закреплён» — нет**: план функции 3 не читает состояние редактора, и оба режима
её снимают.

**`_plan_set_quota` вызывается, хотя заполнение её не читает.** Доли нужны всему,
что идёт после плана — редактору, доливке и сводке; без них «Расширить» на
специализированном плане не положил бы ничего. Сводка показывает их рядом с
пометкой «режим специализации», чтобы было с чем сравнить обычный план на той же
земле.

## Как отличить один режим от другого

`_spec_ran` — флаг для окон (`.IsSet` в `visible`), `_plan_mode` — то же число
для отчёта (`debug_log` печатает только числа). Оба ставит `_spec_run`, оба
снимает `_plan_prepare`, то есть любое «Пересчитать» гасит их само.

- окно плана: строка «режим: специализация» у переключателя свёртки;
- окно сводки: строка о том, что доли и потолки не применялись;
- сводка, причина остановки: код **9** — «его везде перебили», отдельный ответ от
  «ни во что не упёрся»;
- `WTP PASS … mode=1`, и `tools/diag.py` ставит об этом первую строку отчёта.

## Чего нет

**Ни одного прогона.** Не проверено ничего: ни что провинция выбирает грамоту
(`change_global_variable = { add = bag_wtp_rq<k> }` читает **локационную** script
value в обходе по локациям — форма в моде новая), ни сколько товаров остаётся без
единого домика, ни во сколько раз выше общая выгода. Последнее и есть цена
режима, и измерить её можно только на его земле: `GAIN fed=` и средний процент от
потолка рядом с теми же числами обычного плана.
