# Резервация по стеснённости: что строить и что она должна дать

**Заказ владельца, 2026-09-07: «давай пробовать вводить резервацию по
стеснённости».** Ниже — правило, его цена и предсказание, по которому один прогон
скажет, работает оно или нет. **Не построено.**

## Что она чинит, числами последнего прогона

Северная Германия, 416 локаций, 132 города, 284 села; уровень, на который выходят
все, — **61** домик считая РГО. Товары, чей потолок на своей стороне **ниже**
этого уровня, — единственные, кого резервация может тронуть:

| товар | сельских мест | взял | недобрал |
| --- | --- | --- | --- |
| `iron` | 28 | **28** | 0 — взял всё |
| `stone` | 53 | 34 | **19** |
| `salt` | 42 | 31 | **11** |
| `fish` | 42 | 18 | 24 — но 21 из них взяли судовые припасы |
| `naval_supplies` | 42 | 21 | 21 — то же самое с другой стороны |

**Чистые случаи — `stone` и `salt`.** Их сельские здания (`stone_quarry`,
`salt_collector`) не нужны никому другому, то есть за само здание конкуренции нет
— они потеряли **тридцать комнат** тем, у кого в сёлах по 284 альтернативы.
`fish` и `naval_supplies` делят рыбацкую деревню и заняли 39 прибрежных локаций
из 42: там резервация не даст ничего, она лишь переложит места между ними.

**Значит ожидаемая цена — около тридцати комнат**, снятых с товаров, стоящих на
61, то есть по одному-двум с каждого.

## Правило

> **У локации есть хозяин: самый стеснённый из товаров, которые вообще могут
> встать на этой её стороне.** На ступенчатых кругах локация предлагается только
> хозяину (и тем, кто с ним вровень); на общих кругах она открыта всем.

Стеснённость — это `_ngt<n>` / `_ngr<n>`, число локаций выбранной земли, где
товар может встать на этой стороне. Числа уже считаются `_plan_score`.

**Почему «только на ступенчатых кругах» — и это главное в правиле.** Освобождать
локацию, когда хозяин закончил, дорого: пришлось бы на каждую локацию спрашивать,
хочет ли хозяин ещё. А отпускать её на общих кругах того же круга — бесплатно и
даёт тот же результат: хозяин выбирает первым в каждом круге, остальные получают
остаток в том же круге. Никакого состояния заводить не нужно.

## Как строить

**1. Хозяин — одно число на локацию на сторону, считается один раз.** После
`_plan_score` (там `_ngt`/`_ngr` уже окончательны) один обход по `_candidates`:

```
set_variable = { name = _ownt value = 99999 }
set_variable = { name = _ownr value = 99999 }
<на каждый товар n>
  if = { limit = { var:_pm<n> > 0  global_var:_ngt<n> < var:_ownt }
         set_variable = { name = _ownt value = global_var:_ngt<n> } }
  if = { limit = { var:_prm<n> > 0  global_var:_ngr<n> < var:_ownr }
         set_variable = { name = _ownr value = global_var:_ngr<n> } }
```

**`_pm<n>` / `_prm<n>`, а не `_plan_can_*`.** Хозяин — свойство земли, а не того,
что на ней уже стоит; `_plan_can_*` спрашивает свободную комнату и менялся бы по
ходу раздачи. 416 × 47 сравнений один раз — ничто рядом с самой раздачей.

**2. Ворота в `_plan_pick_<n>`**, внутри `limit` обхода, по одной строке на
сторону:

```
OR = {
    global_var:_plan_tier = 0
    var:_own<sfx> = global_var:_ng<sfx><n>
}
```

`_own` — минимум, поэтому `_ng<sfx><n> >= _own` всегда, и равенство означает
ровно «я один из самых стеснённых здесь». `var:x = global_var:y` в моде доказано
(`var:_rtry >= global_var:_rband`).

**3. Обнуление** — там же, где `_load` и `_plan_prank`: в обходе `_plan_prepare`
и в `_ext_prepare`. Доливка считает хозяев заново, потому что новая земля меняет
`_ng`.

**Больше ничего.** Ни флага «хозяин закончил», ни списка, ни второй памяти.

## Чем проверять — предсказание, по которому правило либо живёт, либо снимается

Прогон на той же северной Германии, «Пересчитать», «Диагностика». Ждём:

- **`stone` 45 → около 60**, `salt` 36 → около 47 (в сводке — столбцы «Домиков» и
  «Мест»);
- **товары на 61 опустятся на 1–2** — это и есть заплаченная цена;
- **`fish` и `naval_supplies` не сдвинутся** (они вровень, 42 и 42);
- **`iron` не сдвинется** — он и так взял все свои 28.

**Если не сдвинулось ничего — правило снять**, как сняли ступень по сторонам:
она была верна по смыслу и дала ноль на этой земле.

## Следом — перетасовка внутри провинции

Отдельная работа и отдельный прогон, **после** резервации.

Раздача даёт товару **его** лучшее из оставшегося, а не глобально лучшее, поэтому
после неё остаются пары, обмен между которыми выгоден обоим. По всей земле это
1380 зданий и 957 тысяч пар — слишком дорого для одного нажатия. **Внутри
провинции** — 74 провинции по ~19 зданий, около **12 тысяч пар**, и почти ничего
не теряется: бонус от РГО соседский, обмен между далёкими провинциями выгоды
почти не даёт.

Механизм уже есть и узок: `_edit_reshuffle` торгует только теми зданиями, что
долив поставил после «−1», и только после нажатия в редакторе (`EDIT shuffle` в
отчёте). Расширить его на весь план, ограничив парами одной провинции, и печатать
`GAIN` до и после — иначе «поменяло местами и это ничего не дало» не отличить от
«не сработало».
